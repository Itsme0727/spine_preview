# 项目理解、功能意图与术语表

## 一句话定义

这是一个面向 Spine 动画资产的“可视化动画流程编排器”：用户把动画状态、条件连线、延时/隐藏/循环控制和并行图层放到无限画布中，既能即时预览，又能把整套流程保存、迁移，并交给游戏引擎或 AI 代码工具重建。

项目真正要保存的不是一段视频，而是四层信息：

1. **资产层**：Spine skeleton、atlas、纹理、版本、皮肤、PMA。
2. **状态层**：当前动画、播放速度、循环方式、轨道序列、混合参数、骨骼/插槽/事件标注。
3. **流程层**：节点、端口、条件连线、延时、隐藏、循环、入口/出口。
4. **呈现层**：画布位置、分组、连线曲线、并行层级、容器偏移和预览设置。

只有四层一起导出，另一个 AI 才能同时理解“怎么运行”和“作者在画布上怎么表达”。

## 主要功能

- 导入 Spine 3.8、4.2、4.3 的 JSON/二进制骨架、atlas 与多页纹理。
- 在共享 WebGL 画布和独立预览浮窗中播放动画，设置皮肤、PMA、速度、循环与缩放。
- 用节点和带条件的贝塞尔连线组织完整动画流。
- 用“轨道动画”在同一个 Spine `AnimationState` 上构建多轨叠加；每条轨道内部可以按顺序播放多个动画并原生混合。
- 用“并行播放”同时启动多个分支，并在所有分支（包括嵌套并行）完成后通过栅栏继续主流程。
- 提供视觉延时器、程序延时器、隐藏器、大循环、入口/出口、文本说明、标题和图片参考节点。
- 在骨骼、皮肤、插槽、事件上记录标签、备注、淡入淡出和截图引用。
- 保存/导入工程 JSON 或 ZIP，提供自动保存、撤销/重做、搜索、分组、对齐、吸附和小地图。
- 导出 AI JSON v3，让代码型 AI 或游戏引擎实现者读取规范化流程。

## 运行心智模型

普通流程是有向图。节点完成后，系统读取其出边和条件，选择下一个节点。并行播放节点不是普通动画，它是一个组合调度器：所有层同时开始；每层内部仍是顺序链；遇到子并行时递归执行；只有全部层完成，父流程才能继续。

轨道动画与并行播放是两个不同维度：

- **轨道**发生在一个 Spine 骨架内部，多条 `AnimationState` track 同时作用于同一 Skeleton。
- **并行层**发生在流程和渲染实例层面，多份独立 Skeleton/控制节点同时推进。

因此“把轨道动画节点放入并行层”必须同时保留两套语义，不能退化成只播放 track 0。

## 核心术语

| 项目术语 | 精确定义 |
|---|---|
| 动画状态节点 | 绑定一份 Spine 资源和一组播放参数的流程节点。 |
| 轨道 / Track | Spine `AnimationState` 中按索引叠加的一条独立动画通道。高索引轨道作用在低索引结果之上。 |
| 轨道序列 | 同一轨道内用 `setAnimation + addAnimation` 排列的动画链。 |
| `mixOut` | 当前动画切换到下一动画的重叠秒数，属于“当前动画 → 下一动画”，不是下一动画自身的淡入参数。 |
| MixBlend | 多轨合成方式：setup、first、replace、add。它不是同轨切换时长。 |
| 原生队列 | 由 Spine Runtime 自己维护的 TrackEntry 链，不使用双轨 alpha 模拟同轨淡入淡出。 |
| 混合稳定器 | 对未被任何活动轨道控制的骨骼恢复 Setup Pose，并对混合中新出现且父骨骼大幅移动的附件做短暂 Alpha 门控，抑制“画面乱飞”。 |
| 并行播放 / Layer | 同时启动多条流程分支的组合节点。层号越小，视觉上越靠上。 |
| 并行栅栏 | 所有层和所有嵌套子层完成后才允许主流程继续的同步点。 |
| 链 / Chain | 一个并行层中从起点到下一个嵌套并行或链末尾的顺序节点集合。 |
| 嵌套并行 / Playback Tree | 并行节点内再次连接并行节点形成的递归执行树。 |
| 容器偏移 | 父并行层对其整棵子树施加的位置偏移；子层世界偏移为所有祖先偏移与自身偏移之和。 |
| 隐藏器 | 只抑制绘制的控制节点。隐藏期间分支时间仍推进，否则会造成栅栏死锁。 |
| 视觉延时器 | 在动画链中明确显示并阻塞当前分支一段时间。 |
| 程序延时器 | 语义偏向代码执行等待，但在流程调度中同样按指定秒数阻塞当前分支。 |
| 大循环 | 流程控制节点，触发当前完整路径回到源头。 |
| PMA | Premultiplied Alpha，贴图 RGB 是否已预乘 Alpha；错误设置会产生黑边或混合异常。 |
| Setup Pose | Spine 骨架和插槽的初始姿势，是动画混合基线。 |
| 条件连线 | 带用户原始条件表达式的有向边；项目保存原文，不猜测变量含义。 |
| AI 导出 | 不含二进制资源本体、但完整描述资源引用、规范化图、执行语义和画布呈现的交换格式。 |

## 本轮核心审计与修复

### 轨道混合

- 轨道序列继续使用 Spine 原生队列；`mixOut` 同时设置 TrackEntry 的 `mixDuration` 和正确的开始 `delay`。
- 新增真实序列时长计算：总时长会扣除相邻动画的混合重叠，多轨同时播放取最长轨道。
- 全流程自动推进与并行层内的轨道节点统一使用该时长，不再把所有动画时长直接相加。
- 并行预览现在会为轨道节点建立全部 Runtime track、维持循环队列并应用相同的混合稳定器。
- 修复工程导入的异步闭包错误，避免所有资源恢复回调都错误地应用到最后一个节点。

### 并行播放关键阻断项

- 移除从未同步的旧 `nodeStates` 完成判定，改用实际运行条目的递归完成状态作为唯一栅栏依据。
- 修复 `layer → layer` 直接嵌套被旧兜底逻辑当作普通链重复加载的问题。
- 循环检测改为“当前递归路径私有”，同一个子并行可被不同兄弟分支合法复用。
- 子树缓存按运行实例路径隔离，避免并发分支共享 Skeleton、TrackTime 和位置状态。
- 隐藏层只禁止绘制，继续更新时间线，避免永远无法完成。
- 程序延时器进入顶层与嵌套并行链。
- 切换链节点时当帧立即使用新条目，消除一帧旧画面。
- 自动重播会真正清空并重建 AnimationState，而不只是把链索引归零。
- 并行资源按各自 Spine 版本加载，并补齐 4.2/4.3 `SceneRenderer` 路径。
- 轨道模式与普通模式切换前统一清除 TrackEntry、mixingFrom、队列缓存、临时 Slot Alpha，并从 Setup Pose 重建；同时重建正在引用该节点的并行预览克隆。

## 已知边界

- 仓库没有可用于回归的真实 Spine 资产，因此 Runtime 画面还需要用作者素材做一次最终视觉验收。
- 用户条件是自由文本；AI JSON 保留原表达式，但游戏必须提供变量和求值器。
- AI JSON 不嵌入骨架、atlas 和纹理的巨大二进制内容。达到 100% 还原必须把原始资源文件与 JSON 一起交付。
- 事件截图和部分挂载状态的工程持久化仍有历史欠账，本轮按优先级未扩展处理。
